# Apply Intake — from prototype to finished site

## Inputs
02-intake/owner-answers.txt  — generated by the discovery questionnaire; each question
carries a status line: `answered`, `UNSURE`, `DELEGATED`, or `SKIPPED`, plus optional
`permission_to_investigate`, `who_might_know`, `handled_by`, and `flag:` lines.
02-intake/brief.yaml, assets/, redirect-map.csv — plus everything in 01-baseline/.

## Procedure
1. **Parse the answers by status.**
   - `answered` → authoritative truth. Overwrites any conflicting scraped DRAFT.
   - `UNSURE` + `permission_to_investigate: YES` → resolve technically where possible
     (registrar→WHOIS, email host→MX lookup, platform→tech-fingerprint.md, GA4→detected tag).
     Record each resolution and its evidence in 02-intake/resolved.md.
   - `UNSURE` without permission, `DELEGATED`, `SKIPPED` → goes on the FOR-REVIEW list
     with the captured contact. Never resolved by guessing.
2. **Reconcile brief.yaml**: fill every field the answers or resolutions establish.
   Blanks stay blank.
3. **Replace DRAFT content**: where the owner confirmed ownership of copy, drop the DRAFT
   markers; where ownership is unconfirmed (or flagged), rewrite fresh copy in the brief's
   tone instead of keeping scraped text.
4. **Finalize redirect-map.csv** (new URLs now final) and emit the edge config
   (e.g. public/_redirects in 03-site/). Validate: one hop, no chains, no blanket-to-home.
5. Apply confirmed tokens/assets (real logo.svg replaces placeholder), rebuild
   (`npm run build` in 03-site/), fix failures.
6. Write 04-cutover/launch-runbook.md: ordered launch steps with noindex removal as
   step zero (two-person check), DNS TTL note, form test, email send/receive test.
7. Set status stage=final. Report: APPLIED / RESOLVED (with evidence) / FOR REVIEW.

## Boundaries
Email-affecting items (MX/SPF/DKIM/DMARC) are NEVER acted on — only documented for the
human. Anything `flag:`ged in the answers (e.g. "old vendor unreachable") surfaces at the
top of the FOR-REVIEW list.
